## Filtering Rules

The goal is to plot genuine SSCS changes while suppressing contours created
only by finite-time truncation of otherwise matching symbolic sequences.

Red contours use the `T` SSCSs with the first symbol removed:

```text
T_scs[2:end]
```

This intentionally ignores changes in the first `T` symbol, because those were
not useful for the artifact diagnosis and could create bogus red contours.

Red contours also suppress any marched square whose four corners all have
symbols 2 through 6 equal to zero:

```text
T_scs[2:6] == [0, 0, 0, 0, 0]
```

This removes the large late-symbol truncation artifacts around the regions
where the saved `T` sequences begin with either `[1, 0, 0, 0, 0, 0]` or
`[-1, 0, 0, 0, 0, 0]`.

Both red and blue contours apply prefix-compatibility suppression. A marched
square is skipped if its nonempty corner sequences all match after truncating
the longer sequences to the length of the shortest corner sequence.

For example, no contour is drawn between:

```text
[-1, 8, 8, 8, 8]
[-1, 8, 8, 8, 8, 8]
```

because the longer sequence truncates to the shorter one exactly. This rule is
applied independently to red and blue, with red using `T_scs[2:end]` and blue
using the full `gamma_scs`.

## What The Plot Means

The plot title is:

```text
SSCS changes (t <= 1e5)
```

The `t <= 1e5` qualifier is important: attempt-050 does not save orbit time
series or event times. It saved the SSCSs obtained before the fixed SSCS
integration horizon `ATTEMPT50_SSCS_ODE_TSPAN = (0.0, 1.0e5)`. The filter removes contour
segments that only reflect one corner reaching one extra matching symbol before
that horizon.
